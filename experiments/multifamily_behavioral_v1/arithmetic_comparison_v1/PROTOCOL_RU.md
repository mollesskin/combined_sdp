# Arithmetic comparison v1

RQ: “How effective are combinations of security design patterns compared with their individual components in preventing vulnerabilities in Ethereum smart contracts?”

Это новый поведенческий этап. Наличие статического детектора и совместимость со static-PES не являются условиями включения. PES не вычисляется. Старые screening, пилоты, vendor/pinned, baseline и авторские тесты не изменяются. Следующие этапы — access_control, denial_of_service; здесь выполняется только arithmetic.

Протокол фиксируется до исполнения новых вариантов, но после знакомства с известными baseline-результатами и исходниками: это не preregistration до любых данных. Технический обзор сохранён в review_inputs; предложения проверены по исходникам. Реализация AI-assisted, требует независимой исследовательской проверки, не является текстом assignment.

V0 — побайтовая копия зарегистрированного исходника; V1 — A; V2 — B; V3 — A+B. Точные statements и операнды перечислены в registry.json. A — ResearchChecked: собственная минимальная адаптация идиом post-result add/mul из SafeMath в BECToken данного набора, sub с проверкой b<=a. Это не оригинальный релиз SafeMath. B — inline precondition b<=MAX-a, b<=a, a==0 || b<=MAX/a соответственно. Для subtraction механизмы логически и проверкой неравенства перекрываются; A инкапсулирует checked operation, B сохраняет raw operation с предварительным guard. Идентичный механизм не трактуется как независимый класс защиты. V3 сохраняет оба. Дополнительная польза не предполагается.

BECToken уже имеет SafeMath для остальных операций: treatment только raw cnt*value. В token target включает subtraction в require, debit и последующее credit; guard credit читает промежуточный баланс, поэтому self-transfer проверяется после debit. В tokensale target — обе multiplication и credit/debit. В TimeLock только increaseLockTime, deposit не исправляется. В overflow_single_tx target — три state-changing операции; локальные неиспользуемые res не включены, их поведение не измеряется и не заявляется защищённым.

Общий oracle: математические uint256-операции без wrap; допустимо только 0<=result<=2^256-1 плюс исходные бизнес-предусловия. Для допустимой операции требуется успешное выполнение и точное состояние. Для выхода за диапазон требуется revert с восстановлением наблюдаемого contract state и contract ETH balance, без logs. Атомарный откат оценивается по всем затронутым доступным storage slots/ключам, не как доказательство формальной эквивалентности. ABI equality — лишь проверка интерфейса.

Сценарии зафиксированы в project/measure.js до запуска. Каждый сценарий начинает с hardhat_reset, deploy и одинакового setup во всех вариантах. Набор: ноль, обычный ввод, граница MAX и выход на единицу за границу для add/sub; mul включает zero и максимально допустимый множитель, overflow после достижимого разгона состояния. Для init/run проверяются ранняя ветка, инициализация, безопасное списание и underflow. Mapping не имеет пополнения: допустим только zero debit из исходного нуля, positive debit должен отклоняться. Token — обычные переводы, возврат, zero, self, insufficient credit и self с insufficient credit. BEC — обычный batch, self, повтор получателя и overflow product. TokenSale — buy/sell, zero, insufficient sell, overflow buy с модульной оплатой. TimeLock — deposit/extend, ранний отказ withdrawal, overflow extend, допустимый withdrawal после времени.

Единицы: raw token/count/seconds uint256, ETH в wei, gas в gas units. Все величины BigInt, экспорт десятичными строками. Discrepancy — actual minus mathematical expected для успешных операций с наблюдаемым результатом; для отклонённой операции не подменяется нулём. Wraparound определяется несоответствием точному арифметическому результату с совпадением modulo 2^256, отдельно от иных нарушений. Gas successful и reverted хранятся отдельно по execution_status; суммарной шкалы нет. Ошибки compilation/setup/infrastructure — missing/error, не успешная защита.

Все variants используют скопированную compiler matrix (0.4.24/0.4.25/0.5.0), optimizer и Hardhat Shanghai исходного проекта; точный фактически выбранный solc и settings сохраняются из build-info для каждого artifact. Из config заменён только авторский reporter на spec; dependencies не изменены, node_modules — ссылка на воспроизведённый проект. Выполнение только в локальной Hardhat-сети без forks.

Два полных запуска в разных process/output paths; reset каждого сценария. Повторы не увеличивают размер выборки. AR_ADDER_CLONE сохраняет integer_overflow_add и overflow_simple_add как одну группу; прочие файлы — singleton при данном ограниченном clone review. Это 13 файлов / 12 групп, не доказательство независимости остальных реализаций. Сравнения V3 с V1 и V2 выполняются отдельно по одинаковым сценариям, с учётом functional regression. Результаты ограничены выполненными сценариями и не доказывают отсутствие всех дефектов.

Уточнение инструмента после первого исполнения (сохранено как initial_instrumentation): добавлены arithmetic_trace и field_discrepancies в экспорт, без изменения сценариев, контрактов и oracle. Wrap фиксируется также для intermediate self-transfer и product overflow с указанием вывода по исходнику/операндам; это не выдаётся за EVM opcode trace. Два итоговых запуска используют одну уточнённую измерительную версию. Первое исполнение не включается в размер выборки и не скрывается. До этого уточнения повторный запуск по ошибке перезаписал run1 теми же результатами; пути raw_output в initial_instrumentation исторически указывают на run1. Эти предварительные файлы не используются в итоговой сводке.
