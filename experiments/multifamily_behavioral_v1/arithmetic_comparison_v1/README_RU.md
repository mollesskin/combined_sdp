# Выполненная arithmetic-партия

Рассмотрено 13 зарегистрированных исходных файлов; выполнено 13 полных сравнений V0/V1/V2/V3. Созданы 52 варианта с точными source diffs и SHA-256. Все 52 скомпилированы Solidity 0.4.25, optimizer enabled/runs=200, одинаковые настройки в каждом сравнении. ABI совпали; это не доказательство полной поведенческой эквивалентности.

Два итоговых запуска: по 244 записи, всего 488. В каждом варианте — 61 измеряемый вызов: 43 допустимых (включая setup/ранние ветки), 16 небезопасных арифметических, 2 обычных отказа по исходным условиям. Deploy и reset не считаются отдельными сценариями. 85 проверок evidence прошли; состояния, inputs, receipts/errors, gas и классификации двух запусков совпали с исключением пути raw output.

V0 выполнил все 16 небезопасных вызовов; V1, V2 и V3 отклонили все 16 с полным откатом наблюдаемого состояния. У всех четырёх вариантов прошли все 43 допустимых вызова; функциональных регрессий в выполненных сценариях не обнаружено. Оба исходных обычных отказа сохранены. В случае self-transfer с недостаточным балансом V0 может восстановить тот же конечный баланс, но всё равно нарушает требование no-underflow промежуточного вычисления и безопасного отказа. Это отмечено отдельно от наблюдаемого модульного state result.

V3 против V1: 61 равенство по oracle, 0 улучшений, 0 ухудшений. V3 против V2: также 61/0/0. Дополнительного защитного эффекта комбинации в этом наборе не обнаружено. Это сравнение перекрывающихся арифметических защит, а не свидетельство превосходства комбинации или независимости A/B.

Gas — вторичная метрика. На 43 успешных сопоставимых вызовах V3 потреблял столько же gas в 9 и больше в 34: delta V3−V1 от 0 до 601 gas, V3−V2 от 0 до 345 gas. На 18 отклонённых вызовах (16 unsafe плюс 2 business rejection) delta V3−V1 от −33 до +71 gas, V3−V2 равна 0. Это диапазоны по вызовам, не универсальная шкала эффективности; deployment cost не сравнивался.

По файлам: все 13 полных сравнений завершены. С учётом указанной в обзоре AR_ADDER_CLONE — 12 групп. В каждой группе V0 имеет хотя бы один небезопасный принятый ввод, а все защищённые варианты отклоняют небезопасные и сохраняют допустимые вызовы. Два adder-файла не считаются независимыми реализациями. Остальные singleton-группы также не доказывают независимость; clone review ограничен исходным обзором.

Нет исключённых файлов и незавершённых четырёхвариантных сравнений. Не выполнялись exhaustive/fuzz verification, opcode tracing, formal equivalence и измерение локальных unused res в overflow_single_tx; эти три операции не изменены и не входят в treatment. Достижимый допустимый mapping debit ограничен нулём, поскольку пополнения в исходнике нет. Результаты не обобщаются на непроверенные входы и остальные категории.

## Артефакты

- `PROTOCOL_RU.md`, `registry.json`: правила, targets, ограничения, происхождение helper, группы.
- `project/contracts/V0` … `V3`, `diffs/`: исходники, минимальные изменения.
- `project/measure.js`: единый BigInt-инструмент; `analyze.py`: проверки evidence и агрегация.
- `runs/run1`, `runs/run2`: measurements.json/csv, individual raw receipt/error JSON, ABI, compiler settings.
- `file_summary.csv`, `group_summary.csv`, `comparisons.csv`, `summary.json`: файловая и групповая сводки, отдельные V3−V1/V3−V2.
- `compile.log`, `run2_compile.log`, `run1.log`, `run2.log`, `validation.log`, `versions.txt`, `dependencies.json`, `ERRORS_RU.md`: компиляция, выполнения, проверки, версии и ошибки.
- `review_inputs/`: неизменённые документы технического обзора. `runs/initial_instrumentation` — предварительное исполнение до расширения экспорта; в итоговые результаты не включено.

Для JSON/CSV uint256, wei, seconds, арифметические discrepancy и gas представлены десятичными строками. Малые step indexes/status/chain metadata могут оставаться числами. `expected` для unsafe — состояние до вызова (требуемый rollback); `unsafe_mathematical_state` и `arithmetic_trace` показывают невозможный математический результат. `field_discrepancies` при успешном unsafe вычислены против этого математического состояния, а не против rollback. Арифметический trace выведен из исходника и операндов, не является EVM opcode trace. Reverted discrepancies — null, а не нули.

## Воспроизведение

Из корня репозитория (используются уже установленные зависимости baseline, обновлений нет):

```bash
bash experiments/multifamily_behavioral_v1/arithmetic_comparison_v1/reproduce.sh
```

Команда создаёт новый каталог `runs/reproduction_<UTC>_<pid>`, дважды очищает только новый project, компилирует и исполняет набор в отдельных процессах, затем запускает проверки. Доступ к публичной сети не нужен. `project/node_modules` ссылается на зависимости `stand_reproduction/20261023T024815Z_oJrMgr/project/node_modules`; перенос требует сохранить этот установленный набор. Оригинальный Hardhat config скопирован с единственным изменением reporter на spec; зависимости и compiler/network settings не менялись.

Для перепроверки сохранённых итоговых данных:

```bash
python3 experiments/multifamily_behavioral_v1/arithmetic_comparison_v1/analyze.py
```

`build_variants.py` сохраняет AI-assisted генератор исходников; запускается из корня репозитория и перегенерирует исходники/реестр на основе сохранённого baseline и обзора в Downloads. После генерации реестр требует повторного дополнения execution metadata по новому запуску; для воспроизведения измерений генератор запускать не требуется.

Это локальная AI-assisted исследовательская реализация, не текст сдаваемого assignment. Утверждённый RQ и многокатегорийный план сохранены. Arithmetic-партия завершена; access_control и denial_of_service остаются следующими этапами.

Команда reproduce.sh дополнительно выполнена и проверена: `runs/reproduction_20261023T041750Z_60407`. Ещё два запуска по 244 записи и все 85 evidence checks прошли. Это проверка команды воспроизведения, не дополнительные исходные контракты; основная сводка относится к runs/run1 и runs/run2.
