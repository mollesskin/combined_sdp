# Поведенческий протокол access control v1

RQ неизменен: “How effective are combinations of security design patterns compared with their individual components in preventing vulnerabilities in Ethereum smart contracts?” Следующий этап — отдельная DoS-партия. Arithmetic, baseline, vendor/pinned, static-PES и старые screening неизменны. AI-assisted инженерная реализация; это не текст assignment. Статические детекторы и PES не являются критериями включения, PES не вычисляется.

Этот протокол и measure.js фиксируются до comparative executions этой партии. Авторские baseline-результаты уже известны; это не независимая preregistration до любых данных. В рабочем воспроизведённом project/scripts/test-results.json файл отсутствует при текущем осмотре. Использован фактически сохранённый pinned 0.4.x/scripts/test-results.json: он перечисляет именно 16 access_control файлов; provenance записан в registry. Сохранённый baseline-tests.log 33-файлового воспроизведения скопирован отдельно. Это исторические исходные результаты, не данные новых защит.

## Модели и выбор сравнений

По каждому файлу registry.json содержит protected_asset, permissions, author_test_defect, existing_mechanisms, decision_and_scope и hash исходника/теста. Источник authority не назначается автоматически по названию категории. Разрешённый домен и единый oracle применяются ко всем вариантам, включая baseline. Нет универсального owner-only treatment.

Полные сравнения:

- arbitrary_location_write_simple: V1/A — непустота массива до pop; V2/B — checked subtraction длины с проверкой полученного результата c<=a до присваивания storage; V3 — оба. Эти проверки расположены по разные стороны вычисления, но обеспечивают одно перекрывающееся no-underflow свойство. Не называются независимыми классами атак или двумя опубликованными паттернами. Push/update/pop доступны любому пользователю; Destroy — только исходному owner. Правильный pop пустого массива не должен менять длину/owner или открывать произвольный storage write. Проверяются обычные push/update/pop, OOB update, пустой pop, последующая попытка записи owner и Destroy. Небезопасная последовательность не компенсируется искусственным reset между её шагами.
- wallet_04_confused_sign: V1/A — исправленное entitlement amount<=credit; V2/B — checked subtraction только debit с сохранением исходного >=; V3 — оба. Перенос выплаты/исправление >= в B не допускаются: revert debit откатывает предшествующую transfer. Допустимы zero, partial, full withdrawal не больше собственного credit. Известное исходное ограничение V0/V2 на partial считается унаследованным функциональным дефектом; не скрывается как успешная защита и не приписывается новой регрессии B. V3 против B может улучшить функциональность благодаря A, это не дополнительная защита от второго класса атак.

Single-fix, не полные комбинации:

- incorrect_constructor_name1/2/3 и wallet_03: исправить настоящий constructor с owner/creator=deployer; убрать runtime initializer selector. Исходники описывают ошибку имени конструктора; отдельная post-deploy initialization policy не навязывается. Развёртывание без initializer — общий workflow; у V0 owner остаётся нулевым, и это измеряется как исходный дефект, не выравнивается вызовом уязвимого initializer. ABI/lifecycle изменение раскрыто. В Missing неизвестный selector может попасть в payable fallback и успешно ничего не изменить — допустимая защита, revert не обязателен. Проверки: owner при deploy; пополнение; законный withdraw/partial и migration; outsider init/withdraw/migrate; повторный initializer не должен менять права; права обычного вкладчика сохраняются.
- mapping_write: array→mapping с сохранением public set/get произвольных uint256 ключей. Owner по-прежнему ноль: его init не исправляется, lawful owner withdrawal N/A. Ограничение ключей не добавляется. Get отсутствующего key теперь ноль, baseline мог revert вне длины: документированная семантика mapping, не полная эквивалентность. Artificial funding 1 wei через hardhat_setBalance как в авторском тесте; set ключа, совпадающего с owner slot в исходном array layout, не должен менять owner; withdraw постороннего запрещён. Проверяются small/high/MAX ключи и точные значения.
- multiowned: existing onlyOwner на newOwner. Root/delegated owners могут выдавать права; parent/root удаляют согласно исходному правилу; посторонний не может сам себя назначить. Проверяются дерево делегирования, отзыв, попытки постороннего и выплаты.
- mycontract/phishable: tx.origin→msg.sender. Прямой вызов owner к произвольному receiver разрешён; intermediary сам по себе не получает полномочий от origin. Никаких signatures/allowlist. mycontract финансируется до CREATE по вычисленному адресу; phishable — через существующий payable fallback. Проверяются direct owner, direct outsider и вызов relay при origin=owner.
- parity: только модель прямо развёрнутого WalletLibrary, соответствующая авторскому тесту. Deployer вправе вызывать initWallet/initMultiowned/initDaylimit; outsider не вправе даже первым. Deployment authority guard на всех трёх entrypoints; only_uninitialized сохраняется. Новое private поле добавлено после старых полей. Это single missing-authorization fix; существующий once guard не считается новой B. Проверки трёх отдельных first-entry атак, legit initialization, repeated init, owner/nonowner execute, сохранение harmless nonowner no-op, daily limit/owners, owner kill. Не утверждается применимость к delegatecall proxy: требуется отдельное решение authority/storage в proxy context.
- simple_suicide: новый private deploymentOwner и guard на lifecycle. В исходнике authority отсутствует; модель deployer обоснована ролью owner в functional test, явно вводится как модель этого эксперимента, а не исторический факт. Delay/multisig не выдумываются. Исходная сигнатура без аргументов; ошибочный лишний owner argument старого теста не переносится. Законное и запрещённое завершение проверяются в Shanghai, включая code и ETH. Финансирование до CREATE, поскольку payable entrypoint отсутствует.
- unprotected0: применить существующий onlyowner к changeOwner. Сохраняется одношаговый workflow и разрешённый домен адресов, без zero-address guard. Проверки outsider/no-effect, разрешённая передача и действие нового owner, отказ старому owner.
- wallet_02: погасить user credit перед refund transfer (accounting/CEI). Не запретить вкладчику возврат. Последовательные refunds не должны платить повторно; zero refund может успешно ничего не сделать. Проверки deposit/partial withdraw/refund/repeat/new deposit/refund, failure rollback при отклоняющем получателе, creator migration и outsider migration. Это исправление учёта; mutex не является второй защитой от последовательных выплат.

Нерешённые: FibonacciBalance — определить права setStart/fallback и точный Fibonacci payout workflow перед изоляцией вычисления; proxy — определить доверенные targets и участников forwarding. Только V0 сохраняется/компилируется; comparative execution/защитные показатели N/A, конкретные причины в registry. Не исключаются из 16 и не заменяются. Итоговый план: 2 полных сравнения, 12 single-fix, 2 unresolved; это план охвата, а не утверждение результата.

## Измерения и сопоставимость

measure.js содержит точные сценарии, участников и суммы. Каждый scenario: hardhat_reset, одинаковые signers и deploy order, amounts и gasLimit=6000000. New constructor initial owner различается как непосредственно измеряемое лечение, а внешние условия deploy одинаковы. Существующие исходные ABI используются для низкоуровневой кодировки удалённых initializer entrypoints. ABI comparisons не доказывают эквивалентность. Compiler matrix, optimizer и сеть скопированы из baseline (0.4.24/0.4.25/0.5.0; Shanghai, initialDate). Reporter заменён на spec; dependencies не устанавливаются/обновляются, node_modules — ссылка на установленный baseline. Actual compiler/settings сохраняются из build-info.

Для разрешённой операции нужны успешность и точное expected состояние/ETH payout. Для запрещённой нужен no forbidden effect; корректны revert+rollback или success/no-effect. Отсутствие revert само по себе не failure. Запрещённый lifecycle должен сохранять code; логические owner/integrity нарушения и денежные последствия сохраняются отдельными показателями, не суммируются в число уязвимостей. При revert проверяется всё наблюдаемое затрагиваемое состояние, contract balance, получатели, logs (account gas корректируется). Это observed rollback плюс EVM revert status, не формальная проверка всего пространства storage.

BigInt в вычислениях; uint256, wei и gas в JSON/CSV десятичными строками. Consequences: outflow из contract в wei; recipient gains в wei с исключением tx gas, state differences/owners/credits в своих единицах; discrepancy actual−expected по применимым числовым полям. Owner address — адрес, не денежная величина. N/A/null остаются null с applicability, infrastructure/setup/compilation error — missing/error, не success или ноль. Gas вторичен и сравнивается только для совпадающих входов/before и одинакового execution status; нет универсальной шкалы.

Два отдельных процесса с clean compile и новыми output paths; каждый сценарий reset. Считать файлы, группы, варианты, scenarios и tx observations отдельно. AC_INIT_CLONE содержит три Missing-файла: всего 16 файлов/14 групп по данному ограниченному обзору; это не доказательство независимости singleton. V3 отдельно сравнивается с A и B по security и allowed functionality, с сохранением ties, improvements, worsenings и регрессий. После этого остановиться; DoS не выполнять.

Детали fixture до запуска: arbitrary wallet и Phishable финансируются fallback на 10 wei; mycontract/simple_suicide prefund на 10 wei; mapping artificial funding 1 wei. Для проверки rollback refund используется contract fixture ResearchRejector с reverting fallback: ему локально задаётся тестовый ETH balance и временно impersonate выполняется deposit 5 wei, с stopImpersonating в finally; refund затем вызывается настоящим контрактом через invoke. Это только Hardhat fixture, не реальная учётная запись. Для последовательных deposit/withdraw/refund oracle ведёт отдельный claim ledger по разрешённым требованиям, чтобы stale credit baseline не легитимизировал повторную выплату. Все средства и gas budgets тестовые.
